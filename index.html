Обязательные платежи

Известные суммы уже внесены; неизвестные можно заполнить вручную
Логика источников: доходы 8-го, 10-го и 25-го числа в первую очередь резервируются на все обязательные платежи месяца. Если этой суммы недостаточно, дефицит покрывается из остальных доходов месяца.
Пока отдельная разбивка не задана, в итогах автоматически учитываются известные общие суммы: интернет + мобильная связь — 3 000 ₽/мес., страхование Марата — 25 000 ₽ в мае, страхование студии — 27 500 ₽ в мае, налоги имущество + Lada — 15 000 ₽ в октябре. Как только ты заполнишь соответствующие отдельные строки, общая временная сумма перестанет учитываться, чтобы не было двойного счёта.

Поступления цикла

Учитываются все поступления, попадающие внутрь цикла с 8-го до следующего 8-го. Дата следующего 8-го относится уже к новому циклу.

Переводы цикла

Каждая строка — одно воскресенье внутри цикла. Дата перевода не переносится на будний день: поступления используются только для проверки, хватает ли денег к этому воскресенью.
Это внутреннее распределение денег, а не новый расход. Календарь не увеличивает сумму расходов и не списывает её второй раз из фондов.

Денежный водопад месяца

8-е + 10-е + 25-е → обязательные платежи. Если их не хватает, обязательные добираются из остальных доходов. Затем идут прочие расходы, а остаток распределяется по фондам.
Распределение в фонды и планирование прочих расходов начинается с 08.09.2026. До этой даты приложение не создаёт ретроспективных отчислений в фонды. «Прочие расходы» в этом расчёте = ежемесячные расходы из вкладки «Расход жизнь» + праздники, дата которых приходится на этот месяц.

Распределение дохода между счетами

Система работает по приоритетам: сначала финансируются счета с меньшим номером приоритета, затем следующие; счёт типа «Остаток» получает всё, что осталось.
Стартовая схема: Сбер 75 000 ₽ → Банк Россия 35 000 ₽ → Райффайзен 171 000 ₽ → Т-Банк 30 000 ₽ → весь остаток на накопительный счёт. Это именно схема движения денег между банками. Лимиты и приоритеты можно изменить под фактические счета.

Только это устройство
Supabase уже подключён к Oaks Finance 8.2. Project URL и публичный Publishable key встроены в приложение. Для синхронизации на новом устройстве нужен только вход по e-mail.
Вход по логину и паролю
Один и тот же логин и пароль используются на iPhone, Mac и других устройствах. Письма, вход по ссылке, одноразовые коды и SMTP не используются.
Supabase настроен. Введи e-mail и пароль.

Что осталось настроить один раз

  1. В Supabase открой Authentication → Users.
  2. Нажми Add user → Create new user.
  3. Задай e-mail как логин и постоянный пароль.
  4. Если есть переключатель Auto Confirm User — включи его, чтобы вход не требовал подтверждения письмом.
  5. В Oaks Finance на каждом устройстве введи этот же логин и пароль → «Войти».
  6. На устройстве, где сейчас находятся правильные данные, после первого входа один раз нажми «Загрузить это устройство → облако».
После этого другие устройства с тем же входом будут получать общую актуальную базу автоматически. IndexedDB продолжает работать как локальная резервная копия.
